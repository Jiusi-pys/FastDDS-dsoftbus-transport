## Complete-record framing contract

`ReadSpec.framing` and `classify_record(..., framing=...)` default to `LF_TERMINATED`: a complete terminating LF is required. Explicit `LF_EXCLUDED` is format metadata only for a caller that independently established a complete record boundary and removed only the final LF. A match or the65/77-byte window lengths cannot establish that boundary or grant access. Each mode accepts only zero, one or two trailing CR characters before that boundary, with no internal CR/LF/NUL; truncated records, extra characters and unsupported records stay UNKNOWN. Bare-record behavior therefore changed: consumers with independently confirmed LF-excluded records must specify that framing explicitly.

`PUBLIC_DEVICE_SELECTION_FAILURE` extends the controlled template enum and still denotes failure, not permission or communication success. The output schema structure, CLI denial, IO/ranges and native identity/path/handle protections are unchanged; `further_action_authorized` is always False. Public-source8efffcf2fa2f5d4f997f2de8eb287432959417c8 EchoClient printing (server_for_client.cpp421-442/982/1398) independently yields natural65/77-byte complete-record positives.
