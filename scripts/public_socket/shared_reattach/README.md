# Shared reattach task templates

These are versioned successors of the task-local tools used by the repeated hot-reattach work package. Historical device runs used their recorded artifact paths and hashes, not this directory. Canonical collector/stream/load helpers live one level above; materialization copies those exact current bytes into the task layout.

`materialize.py --repo <absolute repository> --task <repo>/.artifacts/<group>/<fresh-task> --private-config <absolute private JSON>` performs local copying only. It creates a manifest and private task/repository binding, never a DEVICE_CONTRACT, acceptance, claim, permission grant, query, or process. Existing destinations are rejected. The example configuration is deliberately invalid until filled with explicit private values; keep real configurations outside Git.

Private input contains distinct A/B board and token mappings, an absolute HDC executable (no PATH fallback), the independently built query helper path, and exact permission baseline hashes. The reviewed contract and prepared window must bind the private-file SHA. The contract also binds MATERIALIZATION.json and every required copied execution file (using destination paths, not only template-source paths), plus the exact repository NativePermissionGuard.ps1 and formal analyze_shared.py as the two required external executed project dependencies. The window must carry those same guard/analyzer bindings; an omitted map is not an empty-success case. Missing, extra, duplicated or changed task dependencies fail the gate. Python checks the complete closure before loading the private-profile helper; the real Node entry also checks the materialized closure and its window copies. Both gates check the bound identity. The repository/task layout is exact so old relative-root assumptions cannot silently target another checkout.

Each new execution still requires an explicit reviewed task-local plan, immutable admitted contract, source/executor/build/package manifests, declared external helpers and platform preflight, and applicable user authorization. This repository provides no current device allowance. Historical claims, accepted contracts, board identities, maps, native permission JSON, SDK/DSOs and raw device evidence are not distributed. A clone is not a complete evidence backup and cannot execute a device window merely by materializing templates.

Prospective query admission requires the appropriate unspent claim. Completed-query validation is read-only and instead checks that exact consumed claim, original command/output/exit/recovery evidence, historical executable identity and new validator identity. Repeated analysis writes fresh derived output; it does not refund a claim or create permission. Data and query ledgers remain separate. No `allow_consumed` dispatch flag or general-purpose permission bypass is supplied.

`tests/public_socket_executor` exercises the actual materialized prepare/claim/completed-query/route/data-preparation path using explicit local Python/Node children and synthetic guards/text. Its dummy package/helper attestations establish no SDK/device result. Private-profile failure, foreign root, source/hash drift, concurrent claims, normal/tail/incomplete output, termination receipts and no-release-after-failure are covered. Delayed-close/kill-error injections are explicitly distinguished from OS behavior.

Historical finite validation and cumulative runtime boundaries are summarized in `docs/repeated-hot-reattach-baseline.md`. New template/profile wiring is Host-tested separately; it is not retroactively attributed to the prior device executors.
